hAiity / design change proposal

Statistics & Settings,
one visual system.

A concrete design change for the two pages that currently feel assembled rather than designed. Mockups, not app screenshots. Nothing here is implemented.

The rule

Spend the visual effort where the product is — the contribution grid, the user's chosen background, the one number that matters today. Everything else stays quiet and native. Fancy means structure, depth and one signature moment per page, not more glass and more cards. Glass stays on the functional layer: tab bar, sheets, context menus, header blur.

What changed

cutThe three-column footer. Offen, Aktuelle Serie and Diese Woche repeated the sentence above them and were repeated again by the tiles. The one sentence now carries all three, which also restores the metric to VoiceOver.

cutThe 2×2 icon tile grid. Heute and Diese Woche were always on the page, so offering them as optional tiles was noise. Check-ins survives as a quiet chip in the section header; longest streak can be the second tile if you want it.

cutThe streak chip on Rhythmus. The grid is already the streak. A flame in a tinted capsule is also glass in the content layer, which the design system reserves for the functional layer.

cutThe flame colour ramp. Orange to red after 7 and 30 days is a habit-app cliché and it competes with the user's own palette. A streak is a number.

addRhythmus as the one open band. No card, minimal padding, close to the gutter. The wallpaper is visible around it, so the page has one deliberate moment instead of five equal cards.

addSeven days as tiles. The week strip now uses the same squares and ramp as every other graph in the app, so one visual language covers today, the week and the months.

addOne number voice. largeTitle and tiles both use the default design with monospaced digits. .rounded is dropped: the grid is the distinctive shape, rounded type is not needed on top of it.

addOne card, then open sections. A single surface for today, then a continuous canvas for rhythm, week and habits.

What changed

addOne status panel first. iCloud and GitHub are the two things that silently change how the app behaves. Today they are scattered across group headings. The first thing on the page now answers "is this working for me".

cutFour headings became two. Verwalten, Verbindungen, Persönlich, Werkzeuge groups by taxonomy, not by what a person is doing. Everyday, Konto, Archiv & Über reads as three jobs.

cutThe Pro card became a pill. A single row that says what it unlocks, instead of a fourth section with a paragraph. It stops competing with the settings that are free.

cutThe tinted icon square on every row. Thirty-two identical tinted squares are decoration. Plain SF Symbols in the shared 32 pt slot look intentional; if you want colour, tint per group instead of per row.

addMore air per group. Same moreHubGroup and moreSettingsSurface tokens, fewer groups, so the page can breathe without a new token.

keepEverything else. Row order, identifiers, the full-row timezone Menu, the GitHub disconnect action, and every existing accessibility identifier stay as they are.

What changed

addOne surface family across the whole settings area. This is the single change that makes the hub and its sub-pages feel like one product instead of a custom hub plus four stock iOS screens. It reuses moreSettingsSurface, moreSettingsSection and the shared page header that already exist.

addRows explain themselves. Each toggle gets one short consequence line, so the label does not have to carry both settings and behaviour.

cutThe hairline grid. Full-width separators between every row read as a table. One inset divider per group at the 48 pt icon edge, same as the hub, reads as a list of related things.

keepNative Toggle and Menu. They stay in the trailing slot, keep their own hit testing, and keep the system look. Only the row around them changes.

noteThis is the largest job in the proposal. Account, Mitteilungen, Appearance and GitHub each have real state and timing behaviour, so this pass is separate from the hub and the Stats change.

The floor that does not move

Accessibility

  • Every row still has a 44 pt hit target and a 52 pt default rhythm, so a decorative icon never shrinks the target.
  • The Heute card keeps one accessibility element with a value that includes streak and week, since the footer is going away.
  • The Rhythmus grid needs a value that describes the range, not just the title "Die letzten fünf Monate".
  • Titles and captions wrap at AX5. Today they use lineLimit(1) on tile captions, which will clip in German.
  • Status is never colour-only. The iCloud dot is paired with its label.

Appearance and motion

  • The open Rhythmus band must stay legible over every user background, including photos, in light and dark, so it needs the same readability treatment the full-screen background already has.
  • Reduce Transparency turns the status and Rhythmus surfaces solid without changing hierarchy.
  • Increase Contrast must keep the open band distinct from the canvas.
  • Nothing here adds a new animation. The one motion worth considering later is the tile transition on refresh, and only if measurement says the current one is wrong.

Sequence

  • 1. Stats hierarchy. One page, screenshot before and after in light and dark, English and German, default text and AX3. Lowest risk, clearest payoff.
  • 2. Settings status panel and group collapse. Structure only, same tokens, same rows. No new component.
  • 3. Sub-page surface migration. The large job, with its own verification pass.
  • 4. Contract update in haiity-ui-design-system.md alongside step 1, not at the end.

This is the first source change in a while that would justify a new TestFlight build. The next archive is 212 or higher; nothing here should be uploaded from this Mac, so the upload stays on Xcode Cloud.

What this deliberately does not do

Not on the table

  • Glass on content. The tab bar, sheets, context menus and header blur already own it.
  • Gradients, glows, or shadows on the canvas. The user's wallpaper is the gradient.
  • A new accent colour, a second type ramp, or any new token unless it has three callers.
  • A hero number with a small label and a gradient accent. The grid is the hero.
  • Bigger cards. If a section does not earn its height it gets shorter or goes.
  • New insights, trends, or AI. This is a reading page, not a coaching surface.

Why the restraint

Place items to convey their relative importance. People often start by viewing items in reading order.

layout.md › Visual hierarchy

Charts are visually prominent, so take advantage of that prominence by clearly communicating what people can learn from the data they care about.

charting-data.md › Best practices

If multiple charts in your app serve a similar purpose, use a consistent visual approach so people can use what they learn from one chart in another.

charting-data.md › Designing effective charts

The current page already fails the last one quietly: the same week is a bar chart, a percent tile and a column. The proposal fixes that by making every data mark the same square.
